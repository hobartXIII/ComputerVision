🏛️ 進階影像視覺模型（Part 1）

1. 本章重點摘要

本章介紹經典的 CNN 架構演進：從最早的 LeNet、AlexNet，到「越深越好」的 VGG，再到用多種 filter 並行、並用 1×1 卷積省運算的 Inception，以及用殘差連接（Skip Connection）解決深層網路訓練困難的殘差網路（Residual Network, ResNet）。後半轉向輕量化：SqueezeNet 用 Fire module 壓低參數量，MobileNet 用深度可分離卷積（Depthwise Separable Convolution）壓低運算量，EfficientNet 則用複合縮放（Compound Scaling）同時放大深度、寬度與解析度。這章把 C2 的 CNN 基礎與 C3 的改進技巧（BN、正則化）串成實際的經典模型，也是之後遷移學習、物件偵測等章節常用的骨幹網路（backbone）來源。

講義標註「(Skip)」的 LeNet、AlexNet、EfficientNet 三節不在考試範圍，內容保留僅供參考，標題都標上「不考」。檔名為 part1，後續應還有 Part 2。

2. 章節大綱

2.1 LeNet（不考）

  • 1995 年提出，用於美國郵遞區號的手寫數字辨識（MNIST）
  • 架構：兩層 Conv ＋ Max Pool（2×2、stride 2）
    • Conv1：6 個 5×5 filters（stride 1、padding 0）
    • Conv2：16 個 5×5 filters（stride 1、padding 0）
    • 第二次 Max Pool 後，5×5×16 展平成 400 個節點 → FC 120 → FC 84 → 輸出 10 類
  • 在 MNIST 達到 99.3% Accuracy
  • 逐層尺寸與參數量見 2.1

  • 熟悉「卷積 → 池化 → 全連接」的計算流程，後面 VGG、ResNet 都用同樣的方法推算。
  • 可以看出參數主要集中在全連接層，這也是後來 GAP 要取代全連接層的原因。

逐步展開：LeNet 的尺寸一路怎麼變（不考，但是很好的尺寸練習）

  1. Conv1：\(32-5+1=28\)，6 個 filter → \(28\times28\times6\)；參數 \((5\times5\times1+1)\times6=26\times6=156\)
  2. Pool1（2×2、stride 2）：\(28\div2=14\) → \(14\times14\times6\)；pooling 沒有參數、不改通道數。
  3. Conv2：\(14-5+1=10\) → \(10\times10\times16\)；每個 filter 深度要等於輸入的 6：\(5\times5\times6=150\)，加 bias 151，\(151\times16=2{,}416\)
  4. Pool2：\(10\div2=5\) → \(5\times5\times16\)；Flatten：\(5\times5\times16=400\)
  5. 三層 FC：\((400+1)\times120=48{,}120\)；\((120+1)\times84=10{,}164\)；\((84+1)\times10=850\)
  6. 合計：\(156+2{,}416+48{,}120+10{,}164+850=61{,}706\)。和 VGG 一樣，大部分參數在 FC。

2.2 AlexNet（不考）

  • 2012 年提出（比 LeNet 晚 17 年），ILSVRC 2012 冠軍 待確認講義寫成「ILSVRX」，應為 ILSVRC
  • 共 8 層：前 5 層 Conv、後 3 層 FC
  • 超過 6,000 萬（60M）參數，用兩張 GPU 訓練超過一週

2.3 VGGNet

🎯 目的：用規整的「多層 3×3 卷積 ＋ Pooling」把網路加深，提升準確率。

✅ 效果：結構規範、準確率高（ImageNet top-5 92.7%）；但參數龐大（約 1.38 億），計算需求大。

公式：先複習：一層卷積的三個數字 補充

這章幾乎所有計算都是在算同一件事：一層卷積的「輸出尺寸」、「參數量」、「乘法次數」。把這三個算熟，後面的瓶頸層、Depthwise、Fire module、GAP 都只是換數字套進去。

符號意思講義例子
\(N\)輸入的高與寬（假設是正方形）12
\(C_{in}\)輸入通道數（RGB 就是 3）3
\(k\)kernel（filter）大小，\(k\times k\)5
\(p,\ s\)padding、stride（C2 教過）0、1
\(C_{out}\)filter 個數 ＝ 輸出通道數128
\(H,\ W\)輸出的高與寬8
$$\text{① 輸出尺寸}\quad H=W=\left\lfloor\frac{N-k+2p}{s}\right\rfloor+1$$ $$\text{② 參數量}\quad(\underbrace{k\times k\times C_{in}}_{\text{一個 filter 的權重}}+\underbrace{1}_{\text{bias}})\times C_{out}$$ $$\text{③ 乘法次數}\quad\underbrace{H\times W\times C_{out}}_{\text{輸出有幾個數字}}\times\underbrace{k\times k\times C_{in}}_{\text{每個數字要乘幾次}}$$
  • 一個 filter 的深度一定等於 \(C_{in}\)：輸入有 3 個通道，5×5 的 filter 其實是 5×5×3 的一塊，一次把三個通道一起乘完再加總，得到一個數字。
  • 參數量和 \(N\) 無關：同一個 filter 掃過整張圖都用同一組權重（權重共享），圖變大，filter 不會變大。
  • 乘法次數和 \(N\) 有關：圖越大，filter 要停的位置越多，每個位置都要算一次。
  • 所以「參數少」和「運算少」是兩回事，這是 SqueezeNet 和 MobileNet 差別的關鍵。

🎯 目的：一次掌握一層卷積的輸出尺寸、參數量、乘法次數。

🔁 後續用途 補充

  • 本章所有「省運算」的設計（1×1 瓶頸層、Fire module、Depthwise Separable、GAP），都是用這三個數字比較改前改後差多少。
  • 判斷模型能不能放上手機、能不能即時執行：參數量決定佔多少記憶體，乘法次數決定跑多快。

逐步展開：講義例子 12×12×3 輸入、128 個 5×5 filter、padding 0、stride 1

  1. 輸出尺寸：\(\frac{12-5+0}{1}+1=8\)，所以輸出是 \(8\times8\times128\)。 5×5 的框在 12 格寬的圖上，從第 1 格滑到第 8 格就碰到邊了（8 + 5 − 1 = 12），所以每列只有 8 個位置。通道數 128 來自 filter 的個數。
  2. 一個 filter 有幾個權重：\(5\times5\times3=75\)，再加 1 個 bias，共 76。 filter 的深度要和輸入一樣是 3。
  3. 參數量：\(76\times128=9{,}728\)。 128 個 filter，每個 76 個參數。注意這裡完全沒用到 12（輸入大小）。
  4. 每個輸出數字要乘幾次：filter 蓋住的 \(5\times5\times3=75\) 個數字各乘一次權重，共 75 次乘法。 （之後再加起來、加 bias；講義只數乘法，所以加法不算。）
  5. 輸出總共有幾個數字：\(8\times8\times128=8{,}192\)。
  6. 總乘法次數：\(8{,}192\times75=614{,}400\)，這就是講義「一般卷積 614,400 次乘法」的由來。 講義的寫法是 \(75\times64\times128\)：先算一個 filter 掃完整張圖 \(75\times64=4{,}800\) 次，再乘 128 個 filter。順序不同、答案一樣。

卷積三數字計算器（逐步代入）

輸入任何一層卷積的設定，下方會把三個公式逐步代入數字。預設是講義的 MobileNet 例子（應得到輸出 8×8×128、參數 9,728、乘法 614,400）。按「套用」可以看本章其他例子用的是同一套算法。

套用：
  • 2014 年提出，ImageNet（1000 類）top-5 Accuracy 92.7%
  • VGG16：13 層 Conv ＋ 3 層 FC；VGG19：16 層 Conv ＋ 3 層 FC
  • 是「典型 CNN」的範本：多層 Conv 後接 Pooling，filter 數量逐漸增加，最後接 FC
  • 準確率高但訓練很慢，參數量龐大（VGG16 約 1.38 億）
  • 優點：「深度」網路設計、規範的結構；缺點：計算需求大、參數冗餘
  • 補充為什麼全部用 3×3：兩層 3×3 疊起來的感受野等於一個 5×5（三層等於 7×7），但參數比較少（每對輸入／輸出通道 \(2\times9=18\) 對 \(25\)；\(3\times9=27\) 對 \(49\)），而且每層後面都有 ReLU，多了幾次非線性。小 filter 和大 filter 怎麼選，見 C2 2.4

VGG 逐段參數量：參數都跑去哪了？

補充講義「龐大的參數量」那頁的圖未能擷取，這裡直接逐層算（輸入 224×224×3、3×3 卷積 same padding、含 bias）。VGG16 合計應為 138,357,544。打開「FC 換成 GAP」看看 ResNet、SqueezeNet 的做法能省掉多少。

2.4 Inception Network

🎯 目的：不必選 Filter 大小：在同一層並行多種 Filter擷取多尺度特徵，並用 1×1 卷積降低運算量。

✅ 效果：同時抓到細節與大範圍的特徵；Bottleneck Layer 讓運算量降到約 1/10。

  • 動機：設計 CNN 要決定很多超參數（filter size、stride、padding、層數、FC 層數…），其中 filter size 最難選：小 kernel 擅長捕捉細節，大 kernel 擅長捕捉較大範圍的特徵
  • 想法：不必選，在同一層並行使用多種 filter size，再把結果串接，讓網路自己學
  • Inception V1（又稱 GoogLeNet）由 Google 於 2014 年提出，ILSVRC 2014 分類冠軍
  • Inception module：
    • 並行使用 1×1、3×3、5×5 卷積與 max pooling
    • 所有分支用 same padding、stride = 1，輸出寬高相同，才能在通道方向串接（concatenate）
    • max pooling 不改變通道數，所以 GoogLeNet 在 pooling 後接 1×1 卷積，把 192 個通道壓成 32 個
    • 不同 kernel 大小對應不同感受野（Receptive Field），可同時擷取多尺度特徵
  • 運算量問題 → 用 1×1 卷積當瓶頸層（Bottleneck Layer）：先把 192 通道壓到 16，再做 5×5 輸出 32 通道，乘法次數從約 120M 降到約 12.4M（約 1/10）；只要壓縮比例合理，對準確率影響不大（計算見 2.4）
  • 整體設計：Stem → 多個 Inception Block → 輸出；部分版本有輔助分類器（Auxiliary Classifier）
    • Total Loss = Main Loss ＋ \(w_1\) × Auxiliary Loss1 ＋ \(w_2\) × Auxiliary Loss2
    • 輔助分類器只在訓練時使用，推論時移除
  • 名稱由來：作者引用電影「全面啟動（Inception）」的「We need to go deeper」迷因；deeper 有雙關：模組中再嵌模組的巢狀結構，以及層數加深
  • 優點：多尺度特徵擷取、用 1×1 卷積高效利用運算資源、深層仍可訓練（輔助分類器）；缺點：結構複雜、難移植到資源有限的設備、參數與架構選擇複雜

Inception module：四條路並行再串接

補充用 GoogLeNet 第一個 Inception 模組（3a）的設定：輸入 28×28×192，四個分支輸出 64、128、32、32 個通道。切換「1×1 降維」看運算量的差別；取消「same padding」看看為什麼各分支寬高一定要相同。

公式：1×1 卷積到底在算什麼 補充

1×1 卷積的 filter 只有 1×1 大小，看起來好像「什麼都沒做」，但它的深度是 \(C_{in}\)：它在每一個像素位置，把該位置的所有通道做加權相加。所以它不看鄰居（不改變寬高），只負責混合、增減通道數。

🎯 目的：在每一個像素位置，把所有通道加權組合，改變通道數但不改變長寬。

🔁 後續用途 補充

  • 降維：在昂貴的 3×3、5×5 卷積前先壓少通道，就是 Inception 與 ResNet-50 的瓶頸層，以及 C4-2 的 DenseNet-B。
  • Depthwise Separable Convolution 的第二步（pointwise）就是 1×1 卷積，負責混合通道。
  • 後面再接 ReLU，還能多加一層非線性。

逐步展開：某個像素有 3 個通道 \((2,\ 1,\ 3)\)，用 2 個 1×1 filter

  1. 第 1 個 filter 權重 \((0.5,\ -1,\ 1)\)：\(2\times0.5+1\times(-1)+3\times1=1-1+3=3\) 三個通道各乘一個權重再加總，得到一個數字（先省略 bias）。
  2. 第 2 個 filter 權重 \((1,\ 1,\ 1)\)：\(2+1+3=6\)
  3. 結果：這個像素從 3 個通道 \((2,1,3)\) 變成 2 個通道 \((3,6)\)。每個像素都這樣做，所以 \(H\times W\times3\to H\times W\times2\)，寬高不變。 filter 個數決定輸出通道數。Inception 用 16 個 1×1 filter 把 192 通道壓成 16 通道，就是這個原理。
  4. 代價：每個輸出數字只要乘 \(C_{in}\) 次（這裡是 3 次），比 3×3、5×5 便宜很多。 這就是它適合當「瓶頸層」與 MobileNet「Pointwise」的原因。

公式：Inception 瓶頸層

補充講義文字未寫出特徵圖大小；以下以常見的 28×28×192 輸入計算，結果與講義的 120M、2.4M、10M 吻合。

  • 直接 5×5 卷積輸出 32 通道：\(28\times28\times32\times(5\times5\times192)=120{,}422{,}400\approx120\text{M}\)
  • 先 1×1 壓到 16 通道：\(28\times28\times16\times192=2{,}408{,}448\approx2.4\text{M}\)
  • 再 5×5 輸出 32 通道：\(28\times28\times32\times(5\times5\times16)=10{,}035{,}200\approx10\text{M}\)
  • 合計約 12.4M，約為原本的 1/10

🎯 目的：在大卷積之前先用 1×1 把通道壓少，算出能省下多少乘法。

🔁 後續用途 補充

  • 讓 Inception module 能平行放 1×1、3×3、5×5 等多種卷積，運算量卻不會爆炸。
  • 同樣的想法出現在 ResNet-50 的 bottleneck block 與 C4-2 的 DenseNet-B。

逐步展開：28×28×192 → 32 通道，直接用 5×5 vs 先用 1×1 壓到 16

  1. 先確定輸出大小：Inception 用 same padding、stride 1，寬高不變，輸出 \(28\times28\times32\)；位置數 \(28\times28=784\)。
  2. 直接 5×5：每個輸出數字乘幾次？ filter 是 \(5\times5\times192=4{,}800\)，所以 4,800 次。 filter 深度要等於輸入通道 192，這就是貴的原因。
  3. 直接 5×5：總共：輸出數字 \(784\times32=25{,}088\) 個，\(25{,}088\times4{,}800=120{,}422{,}400\approx120\text{M}\)
  4. 瓶頸第一步（1×1，192 → 16）：每個數字乘 \(1\times1\times192=192\) 次；輸出數字 \(784\times16=12{,}544\) 個；\(12{,}544\times192=2{,}408{,}448\approx2.4\text{M}\)
  5. 瓶頸第二步（5×5，16 → 32）：現在輸入只剩 16 通道，每個數字乘 \(5\times5\times16=400\) 次；輸出數字仍是 25,088 個；\(25{,}088\times400=10{,}035{,}200\approx10\text{M}\) 和第 3 步比，只有「每個數字乘幾次」從 4,800 變 400，降了 12 倍，因為 192 → 16。
  6. 比較：\(2{,}408{,}448+10{,}035{,}200=12{,}443{,}648\)；\(120{,}422{,}400\div12{,}443{,}648\approx9.7\)，約省 10 倍。 多加一層 1×1 本身要 2.4M，但換來 5×5 那層省下 110M，非常划算。

2.5 ResNet

🎯 目的：解決網路很深時難以優化、效能反而下降的問題。

✅ 效果：殘差連接讓層只需學殘差 F(x)，梯度也能經捷徑傳回前面，可以訓練上百層的網路。

  • 一般 CNN 是線性順序的序列；模型很深時效能反而下降，而且不是過擬合（例如 50 層比 20 層還差）
  • 原因之一：梯度爆炸／消失（Exploding／Vanishing Gradients）：N 層網路更新時要把 N 個導數相乘，導數大就指數成長、小就指數消失
  • 解法：把前面的輸入直接加到後面的輸出（殘差連接、skip connection）
  • 講義圖示：普通網路「期望」層數越多 loss 越低，「現實」層數太多 loss 反而上升
  • ResNet34：多個連續 3×3 卷積，特徵圖深度依序 64、128、256、512，每 2 個卷積繞過一次；卷積輸出尺寸不變（padding 1、stride 1）
  • 層數版本：18、34、50、101、152、1202
  • 因為使用 Global Average Pooling，只需少量甚至不需要 FC 層，模型可以更深
  • 優化觀點（為什麼 ResNet 有效）：
    • 理論上更深的網路至少應與淺網路一樣好（多出的層只要學會「什麼都不做」，即恆等映射 \(H(x)=x\)）
    • 傳統 CNN：\(H(x)=\text{Layer}_n(\cdots\text{Layer}_1(x)\cdots)\)，要讓多層非線性網路逼近恆等函數，對 SGD 等優化器很困難
    • ResNet 改寫成 \(H(x)=F(x)+x\)，堆疊的層只需學殘差 \(F(x)=H(x)-x\)；要達到恆等只要 \(F(x)\to0\)，容易很多
    • \(F(x)\) 是多層串起來（卷積 → BN → ReLU → 卷積 → BN），任一層輸出為 0，\(F(x)\) 就是 0
    • 實際上最佳映射通常不會剛好是恆等函數，但若接近恆等，學一個小的修正量 \(F(x)\) 比從頭學整個 \(H(x)\) 容易得多
    • 講義比喻：傳統網路要學生每次從空白紙重畫；ResNet 先給原圖，只要修改需要改的地方
  • 優點：能有效訓練深層網路、ImageNet 表現優於前代、可從 18 層延伸到 152 層並廣泛作為 backbone、降低優化難度加快收斂
  • 缺點：運算量與記憶體需求大，不利部署在行動裝置；許多 block 學到的殘差很小，參數使用效率不佳

為什麼殘差比較好學：讓兩層網路學會「什麼都不做」

補充用一維的小例子模擬一個 block：普通網路 \(H(x)=w_2\,\text{ReLU}(w_1x)\)，ResNet \(H(x)=x+w_2\,\text{ReLU}(w_1x)\)。目標是恆等映射 \(H(x)=x\)（虛線）。調 \(w_1, w_2\) 試著讓兩條曲線貼上虛線：ResNet 只要把 \(w_2\) 拉到 0 就完成；普通網路怎麼調都只能對一半。

梯度要穿過 N 層：普通網路每層乘上導數 \(d\)；ResNet 每個 block 的導數是 \(\partial H/\partial x=1+F'\)，多了一條「+1」的捷徑。

公式：ResNet 殘差學習

$$H(x)=F(x)+x\quad\Rightarrow\quad F(x)=H(x)-x$$
  • 補充反向傳播時 \(\dfrac{\partial H}{\partial x}=\dfrac{\partial F}{\partial x}+1\)，那個「+1」讓梯度至少有一條不會衰減的路
  • 補充梯度消失／爆炸的數值感：20 層每層導數 0.5 → \(0.5^{20}\approx9.5\times10^{-7}\)；每層 1.5 → \(1.5^{20}\approx3{,}325\)（在 2.5 的元件下半部可以驗證）

🎯 目的：讓每一層只學「殘差」\(F(x)=H(x)-x\)，並保留一條直接把 \(x\) 加回來的捷徑。

🔁 後續用途 補充

  • 反向傳播時梯度可以經由那個「+1」直接傳回前面的層，解決深層網路的梯度消失與退化問題，網路才能疊到上百層。
  • C4-2 的 DenseNet 把「相加」換成「串接」，是同一個想法的延伸。
  • C5 遷移學習最常用的骨幹就是 ResNet-50。

逐步展開：梯度為什麼會消失，「+1」為什麼有用 補充

  1. 連鎖律（Chain Rule）：如果 \(y=f_3(f_2(f_1(x)))\)，那 \(\dfrac{\partial y}{\partial x}=f_3'\times f_2'\times f_1'\)，也就是每一層的導數連乘。 C1 反向傳播學過：誤差從輸出往回傳，每經過一層就乘上那一層的導數。
  2. 3 層、每層導數 0.5：\(0.5\times0.5\times0.5=0.125\)，傳到第一層只剩 1/8。
  3. 20 層：\(0.5^{20}=(0.5^{10})^2=\left(\tfrac{1}{1024}\right)^2\approx(0.000977)^2\approx9.5\times10^{-7}\) 梯度小到幾乎是 0，前面的層權重幾乎不更新 → 梯度消失。
  4. 反過來，每層 1.5：\(1.5^{20}=(1.5^{10})^2\approx57.7^2\approx3{,}325\) → 梯度爆炸，更新一次就跳太遠。
  5. 殘差 block 的導數：\(H(x)=F(x)+x\)，對 \(x\) 微分：\(\dfrac{\partial H}{\partial x}=\dfrac{\partial F}{\partial x}+\dfrac{\partial x}{\partial x}=F'+1\) \(x\) 對自己微分是 1，這就是捷徑貢獻的「+1」。
  6. 代數字：如果殘差分支學到的修正很小，例如 \(F'=0.05\)，每個 block 的倍率是 1.05；20 個 block：\(1.05^{20}\approx2.65\)，不會消失也不會爆炸。 對照普通網路 \(0.5^{20}\approx0.000001\)，差了百萬倍。
  7. 「學殘差」的數字例子：輸入 \(x=3\)，理想輸出 \(H(x)=3.2\)。普通網路要從零學出「輸出 3.2」；ResNet 只要學 \(F(x)=3.2-3=0.2\) 這個小修正。如果理想輸出剛好就是 3，\(F(x)=0\) 即可。

2.6 Global Average Pooling（GAP）

🎯 目的：每張 Feature Map 取平均，取代 Flatten ＋ 大型 Fully Connected Layer。

✅ 效果：大幅減少參數、降低 overfitting、對輸入尺寸更靈活；但丟失空間位置資訊。

  • 每張特徵圖取平均：7×7×512 → 1×1×512
  • 優點：
    • 大幅減少參數：GAP 本身沒有可學習參數，取代 flatten 後的大型 FC 層
    • 增強泛化、降低過擬合：參數少、複雜度低，等於一種 Regularization
    • 對輸入尺寸更靈活：FC 要求固定長度輸入；GAP 不論特徵圖是 7×7 還是 10×10 都輸出同樣長度（但解析度差太多準確率仍可能下降）
  • 缺點：
    • 丟失空間資訊：只知道特徵整體強度，不知道在哪裡；對分類影響不大，但不適合直接用於物件偵測、語意分割
    • 小物體訊號可能被稀釋：與大片背景一起平均而被沖淡，有時改用 Global Max Pooling

GAP vs Flatten：一張特徵圖變成一個數字

下面是某一個通道的特徵圖（數值 0～9）。點格子可以切換「有反應／沒反應」，觀察 GAP 和 Global Max Pooling 的差別；預設是一個只佔一小塊的物體（小物體會被稀釋）。下半部比較 flatten＋FC 與 GAP 的參數量，改特徵圖大小看看哪一個的長度會跟著變。

套用：

公式：GAP 省下的參數 補充

  • 7×7×512 展平 = 25,088 維，若接 4,096 節點的 FC（VGG 的做法）：\((25{,}088+1)\times4{,}096=102{,}764{,}544\) 個參數
  • 改用 GAP → 512 維，GAP 本身 0 參數；接 1,000 類輸出只要 \((512+1)\times1{,}000=513{,}000\)
  • 可以在 2.6 的元件改特徵圖大小比較

🎯 目的：把每個通道的特徵圖平均成一個數，取代「展平 ＋ 大型全連接層」，算出能省多少參數。

🔁 後續用途 補充

  • 大幅減少參數、降低過擬合；而且不再受固定的 Flatten 長度限制，輸入圖片的尺寸可以改變。
  • GoogLeNet、ResNet、MobileNet 都用 GAP 接分類層。
  • C5 遷移學習換成新任務時，只要換掉 GAP 後面那一層（例如 2048 → 10）。

逐步展開：7×7×512 接到分類器，Flatten＋FC vs GAP

  1. GAP 對一個通道做什麼：例如某個通道是 2×2 的 \(\begin{bmatrix}1&3\\5&7\end{bmatrix}\)，GAP = \((1+3+5+7)\div4=4\)。一個通道 → 一個數字。 7×7 的通道就是 49 個數字取平均。沒有任何權重要學，所以 GAP 是 0 參數。
  2. GAP 的輸出：512 個通道各取一個平均 → 長度 512 的向量（1×1×512）。
  3. Flatten 的輸出：把所有數字排成一列：\(7\times7\times512=49\times512=25{,}088\) 維。
  4. FC 層的參數量公式：\((\text{輸入長度}+1)\times\text{輸出節點數}\) 每個輸出節點和每個輸入都有一條權重，再加自己的 bias（C2 學過）。
  5. Flatten → FC 4096：\((25{,}088+1)\times4{,}096=102{,}760{,}448+4{,}096=102{,}764{,}544\)，約 1 億。
  6. GAP → FC 1000：\((512+1)\times1{,}000=512{,}000+1{,}000=513{,}000\)
  7. 比較：\(102{,}764{,}544\div513{,}000\approx200\) 倍。關鍵是 FC 的輸入從 25,088 縮成 512，差了 49 倍（就是 7×7）。

2.7 訓練效率 vs 計算成本

🎯 目的：區分「每一步要花多少資源」（計算成本）與「要幾步才能達到目標」（訓練效率）。

✅ 效果：能估計總訓練成本，判斷模型適不適合部署在手機或即時應用。

  • 計算成本：完成一次運算（例如一個 batch 的前向與反向傳播）需要多少資源
  • 訓練效率：需要多少訓練步數（或資料量）才能達到目標性能
  • 總訓練成本 ≈ 計算成本 × 所需步數
  • 四象限：CP 值、直上魂、哪個最便宜、盤子（見 4.3）

公式：卷積運算量

$$\text{FLOPS}_{\text{conv}}\propto H\times W\times C_{in}\times C_{out}\times k^2$$

\(H, W\)：輸出特徵圖高寬；\(C_{in}, C_{out}\)：輸入／輸出通道數；\(k\)：kernel 大小。寬度（通道數）或解析度加倍 → FLOPS × 4；深度（層數）加倍 → FLOPS × 2。

參數量則和 \(H, W\) 無關：\((k^2C_{in}+1)\times C_{out}\)。這就是「解析度只影響運算、不影響參數」的原因（見 2.9）補充。

公式裡的 \(\propto\) 讀作「正比於」：不在乎確切的數字，只在乎「某個東西變成 2 倍，運算量變幾倍」。

🎯 目的：估計一層卷積的計算成本，並看出各個因素放大時運算量會變幾倍。

🔁 後續用途 補充

  • 判斷模型在手機、嵌入式裝置或即時應用上跑不跑得動。
  • 解釋 MobileNet 的 \(\alpha\)、\(\rho\) 為什麼是平方關係，以及 EfficientNet compound scaling 的係數條件 \(\alpha\beta^2\gamma^2\approx2\)。

逐步展開：一層 28×28、64 → 64 通道的 3×3 卷積，分別把寬度、解析度、深度加倍 補充

  1. 原本：\(28\times28\times64\times64\times3^2=784\times4{,}096\times9=28{,}901{,}376\) 直接套 2.3 的 ③：輸出位置 784 個 × 輸出通道 64 × 每個數字乘 \(3\times3\times64\) 次。
  2. 寬度加倍（64 → 128）：\(C_{in}\) 和 \(C_{out}\) 都變 2 倍 → \(2\times2=4\) 倍 → \(115{,}605{,}504\) 這一層的輸出通道變多，下一層的輸入通道也跟著變多，所以兩個都會乘 2。
  3. 解析度加倍（28 → 56）：\(H\) 和 \(W\) 都變 2 倍 → \(2\times2=4\) 倍 → \(56\times56\times64\times64\times9=115{,}605{,}504\) 邊長 2 倍，面積（位置數）是 4 倍。
  4. 深度加倍（多疊一層一樣的）：只是多做一次 → \(2\) 倍 → \(57{,}802{,}752\)
  5. 結論：寬度、解析度的影響是「平方」，深度是「一次方」。這就是 EfficientNet 限制式寫成 \(\alpha\cdot\beta^2\cdot\gamma^2\) 的原因（2.10）。

2.8 SqueezeNet

🎯 目的：維持 AlexNet 等級的準確率，同時大幅縮小模型。

✅ 效果：用 Fire module，參數約 AlexNet 的 1/50，方便傳輸與部署；但參數少不代表運算少。

  • 2016 年提出；目標：維持 AlexNet 等級準確率，大幅縮小模型
  • 小模型的好處：分散式訓練時伺服器間傳輸量少、透過網路更新模型需要的頻寬小（例如自駕車遠端更新）、更容易部署在嵌入式系統
  • 參數量約為 AlexNet 的 1/50，搭配模型壓縮後檔案可小於 0.5MB
  • 三個設計策略：
    1. 把部分 3×3 filter 換成 1×1，每個 filter 參數變 1/9
    2. 減少輸入到 3×3 filter 的通道數（該層參數 = 輸入通道數 × filter 數 × 3 × 3）
    3. 延後下採樣，讓卷積層在較大的特徵圖上運算，維持準確率
    策略一、二減少參數，策略三在參數有限下保持準確率；前兩個策略透過 Fire module 實現
  • Fire Module：
    • squeeze layer（只有 1×1 filter）→ expand layer（1×1 與 3×3 filter 混合）
    • 三個超參數：\(s_{1\times1}\)（squeeze 的 1×1 數量）、\(e_{1\times1}\)、\(e_{3\times3}\)（expand 的 1×1、3×3 數量）
    • squeeze 的 filter 數遠小於 expand（約 1/8），先壓縮再展開 → 對應策略二
    • 講義示意圖：\(s_{1\times1}=3\)、\(e_{1\times1}=4\)、\(e_{3\times3}=4\)
  • 整體架構：conv1 → 8 個 Fire module（fire2～fire9）→ conv10
    • 三次 max pooling 在 conv1、fire4、fire8 之後 → 對應策略三
    • 移除龐大的 FC 層：conv10 用 1×1 卷積直接輸出 1,000 個通道（= 類別數），再經 GAP 送入 softmax
    • 變體：加上 simple bypass 或 complex bypass（類似 ResNet 捷徑）
  • 優點：模型極小、準確率與 AlexNet 相當；結合壓縮可縮到 AlexNet 的 1/510；適合儲存空間或頻寬有限的情境
  • 缺點：準確率只有 AlexNet 水準，明顯低於 VGG、ResNet；參數少不等於運算少，延後下採樣使運算量甚至高於 AlexNet

Fire module 參數量計算器

預設是 SqueezeNet 的 fire2（輸入 96 通道、\(s_{1\times1}=16\)、\(e_{1\times1}=64\)、\(e_{3\times3}=64\)），合計應為 11,920。右邊會和「直接用一層 3×3 卷積得到同樣輸出通道數」比較。含 bias。

套用：

公式：Fire Module 參數量 補充

以 SqueezeNet fire2 的設定為例：輸入 96 通道、\(s_{1\times1}=16\)、\(e_{1\times1}=64\)、\(e_{3\times3}=64\)

  • squeeze：\((1\times1\times96+1)\times16=1{,}552\)
  • expand 1×1：\((1\times1\times16+1)\times64=1{,}088\)
  • expand 3×3：\((3\times3\times16+1)\times64=9{,}280\)
  • 合計 11,920，輸出 64 + 64 = 128 通道；若直接用 3×3 卷積 96 → 128：\((3\times3\times96+1)\times128=110{,}720\)，約多 9 倍
  • 可以在 2.8 的計算器驗算

🎯 目的：用 squeeze（1×1 壓通道）＋ expand（1×1 與 3×3 並行）組成一個模組，算出它比一般 3×3 卷積省多少參數。

🔁 後續用途 補充

  • SqueezeNet 由多個 Fire module 疊成，讓模型小到可以放進記憶體有限的裝置。
  • 和 Inception 瓶頸層一樣，都是「先壓通道、再做昂貴卷積」的思路。

逐步展開：fire2（輸入 96 通道、\(s_{1\times1}=16\)、\(e_{1\times1}=64\)、\(e_{3\times3}=64\)）

  1. squeeze：16 個 1×1 filter，每個深度 = 輸入的 96 → \(1\times1\times96=96\) 個權重 + 1 bias = 97；\(97\times16=1{,}552\) squeeze 之後只剩 16 個通道，這是後面便宜的關鍵。
  2. expand 1×1：輸入是 squeeze 的輸出（16 通道），不是原本的 96！每個 filter \(1\times1\times16+1=17\)；\(17\times64=1{,}088\)
  3. expand 3×3：同樣吃 16 通道，每個 filter \(3\times3\times16+1=145\)；\(145\times64=9{,}280\) expand 的兩組 filter 是並排（同時吃 squeeze 的輸出），不是串在一起。
  4. 合計與輸出：\(1{,}552+1{,}088+9{,}280=11{,}920\)；兩組輸出串接：\(64+64=128\) 通道。
  5. 對照組：直接一層 3×3，96 → 128：每個 filter \(3\times3\times96+1=865\)，\(865\times128=110{,}720\)；\(110{,}720\div11{,}920\approx9.3\) 倍。 省在兩處：3×3 的輸入從 96 壓到 16（策略二）；一半的輸出改用 1×1（策略一）。

2.9 MobileNet

🎯 目的：讓 CNN 能在手機、嵌入式裝置上即時執行。

✅ 效果：Depthwise Separable Convolution 讓運算量降到約 1/8～1/9（3×3），並可用 α、ρ 依裝置效能調整。

  • 2017 年提出；動機：VGG、ResNet 參數與運算量大，手機／嵌入式裝置放不下、推論（inference，即 forward propagation）太慢
  • 行動裝置運算能力低（便宜、省電），需要訓練小模型或壓縮模型
  • 兩個關鍵：Depthwise Separable Convolution 與兩個超參數
  • Depthwise Separable Convolution = Depthwise（每個 channel 各自用一個 k×k×1 的 kernel）＋ Pointwise（1×1 卷積做通道的線性組合）
    • 講義例子運算量約為一般卷積的 1/20（計算見 2.9）
  • 兩個超參數（見 2.9）：
    • Width Multiplier α ∈ (0, 1]：每層輸入輸出通道數都乘 α（常見 1.0、0.75、0.5、0.25）；運算量與參數量約變為 α² 倍
    • Resolution Multiplier ρ：縮小輸入解析度（預設 224，常見 224、192、160、128）；運算量約變為 ρ² 倍，參數量不變
  • 優點：約 420 萬參數（VGG16 的 1/32）、運算量約 VGG16 的 1/27、ImageNet 準確率接近 VGG16、可用 α 與 ρ 靈活調整
  • 缺點：準確率低於 ResNet，α 或解析度太小時下降明顯；運算量減少不一定等比例變快（depthwise conv 在 GPU 上硬體利用率差）；沒有捷徑連接難以加深（MobileNetV2 改進）

公式：Depthwise Separable Convolution

講義例子：12×12×3 輸入、5×5 kernel、輸出 8×8×128

  • 一般卷積：每個位置 \(5\times5\times3=75\) 次乘法，共 \(75\times64\times128=614{,}400\)
  • Depthwise：\(5\times5\times64\times3=4{,}800\)
  • Pointwise：\(3\times64\times128=24{,}576\)
  • 合計 29,376，約為一般卷積的 1/20.9

補充一般式：

$$\frac{\text{Depthwise Separable}}{\text{一般卷積}}=\frac{HWC_{in}k^2+HWC_{in}C_{out}}{HWC_{in}C_{out}k^2}=\frac{1}{C_{out}}+\frac{1}{k^2}$$

驗證：\(1/128+1/25\approx0.0478\approx1/20.9\)；3×3 kernel 時約省 8～9 倍。

🎯 目的：把一般卷積拆成「每個通道各自做空間卷積」＋「1×1 混合通道」兩步，大幅減少乘法次數。

🔁 後續用途 補充

  • 是 MobileNet 的核心，讓 CNN 能在手機上即時執行。
  • 同樣的拆法也用在後來的 EfficientNet 等輕量模型。

逐步展開：講義例子（12×12×3、5×5、輸出 8×8×128）

  1. 輸出位置數：\(12-5+1=8\)，\(8\times8=64\) 個位置。
  2. 一般卷積：每個輸出數字乘 \(5\times5\times3=75\) 次；輸出數字 \(64\times128=8{,}192\) 個；\(8{,}192\times75=614{,}400\) 一個 filter 同時做兩件事：看 5×5 的空間範圍、把 3 個通道混在一起。
  3. Depthwise（只看空間）：3 個 \(5\times5\times1\) 的 kernel，每個只負責一個通道。每個輸出數字乘 \(5\times5=25\) 次；輸出 \(8\times8\times3=192\) 個數字；\(192\times25=4{,}800\) 通道各算各的，輸出仍是 3 個通道（8×8×3），還沒有混通道。
  4. Pointwise（只混通道）：128 個 \(1\times1\times3\) 的 kernel。每個輸出數字乘 3 次；輸出 \(8\times8\times128=8{,}192\) 個數字；\(8{,}192\times3=24{,}576\) 就是 2.4 的 1×1 卷積：在每個位置把 3 個通道加權相加，128 個 filter 得到 128 個通道。
  5. 合計與比值：\(4{,}800+24{,}576=29{,}376\)；\(614{,}400\div29{,}376\approx20.9\)。輸出形狀和一般卷積一樣是 8×8×128，但運算量只要約 1/21。
  6. 推一般式：把三個量都用符號寫（\(H\times W\) 是輸出位置數） $$\text{一般}=HW\,C_{out}\,k^2C_{in},\quad\text{Depthwise}=HW\,C_{in}\,k^2,\quad\text{Pointwise}=HW\,C_{out}\,C_{in}$$
  7. 相除、拆成兩項： $$\frac{HWC_{in}k^2+HWC_{in}C_{out}}{HWC_{in}C_{out}k^2}=\frac{HWC_{in}k^2}{HWC_{in}C_{out}k^2}+\frac{HWC_{in}C_{out}}{HWC_{in}C_{out}k^2}=\frac{1}{C_{out}}+\frac{1}{k^2}$$ 分子分母相同的東西直接約掉。代入 \(C_{out}=128,\ k=5\)：\(0.0078+0.04=0.0478\)。
  8. 直覺：\(C_{out}\) 通常很大（128、256…），所以 \(1/C_{out}\) 很小，比值大約就是 \(1/k^2\)：3×3 約省 9 倍、5×5 約省 25 倍。

套用：

公式：MobileNet 兩個超參數

$$\text{運算量}\propto\alpha^2\rho^2,\qquad \text{參數量}\propto\alpha^2\ \ (\text{與 }\rho\text{ 無關})$$
  • 例：64 → 128 通道的層，α = 0.5 → 32 → 64；運算量與參數量約變 \(0.5^2=0.25\) 倍
  • 例：解析度 224 → 160，\(\rho\approx0.714\)，運算量約變 \(0.714^2\approx0.51\) 倍，參數量不變

🎯 目的：用兩個旋鈕按比例縮小模型：\(\alpha\) 縮通道寬度、\(\rho\) 縮輸入解析度。

🔁 後續用途 補充

  • 依裝置效能在準確率與速度之間取捨，不必重新設計架構。
  • \(\alpha\) 同時省運算與參數；\(\rho\) 只省運算（參數量和解析度無關），要省記憶體就要調 \(\alpha\)。

逐步展開：為什麼 α 是平方、ρ 不影響參數？（以一般 3×3 卷積 64 → 128、特徵圖 112×112 為例）補充

  1. 原本的參數量（先不算 bias）：\(3\times3\times64\times128=73{,}728\)
  2. α = 0.5：輸入 \(64\times0.5=32\)、輸出 \(128\times0.5=64\)；參數 \(3\times3\times32\times64=18{,}432\) \(18{,}432\div73{,}728=0.25=0.5\times0.5\)。一個 0.5 來自 \(C_{in}\)、另一個 0.5 來自 \(C_{out}\)，所以是 \(\alpha^2\)。運算量也同樣乘上 \(\alpha^2\)。
  3. ρ 怎麼算：\(\rho=160\div224\approx0.714\)；特徵圖邊長也乘 ρ：\(112\times0.714=80\)。
  4. ρ 對運算量：位置數 \(112\times112=12{,}544\) → \(80\times80=6{,}400\)，\(6{,}400\div12{,}544\approx0.51=\rho^2\) 高、寬各乘一次 ρ，所以是 \(\rho^2\)。
  5. ρ 對參數量：\(k\)、\(C_{in}\)、\(C_{out}\) 都沒變 → 還是 73,728，不變。 回到 2.3：參數量公式裡根本沒有 \(H, W\)。
  6. 放在一起：運算量 \(\propto\alpha^2\rho^2\)、參數量 \(\propto\alpha^2\)。α = 0.5、解析度 160 時，運算量約 \(0.25\times0.51\approx0.13\) 倍。 MobileNet 實際用的是 depthwise separable 層，depthwise 那一項只和 α 成一次方，所以實際比值會略高於 α²（下面元件可以看到 0.266）。

套用：

2.10 EfficientNet（不考）

  • 2019 年提出
  • 動機：CNN 常在固定資源下設計再放大（例如 ResNet-18 → ResNet-200），過去只調單一維度（深度、寬度或解析度），需大量手動調整且不易達最佳
  • 發現：放大任一維度都能提升準確率，但模型越大增益越小；平衡放大所有維度效果最好
  • Compound Scaling：用固定係數 α、β、γ 同時放大深度、寬度、解析度，由 φ 控制放大程度（見 2.10）
  • 網格搜尋兩步驟：
    1. 固定 φ = 1，對 Baseline 做小範圍網格搜尋，得到 B0 的 α = 1.2、β = 1.1、γ = 1.15
    2. 固定 α、β、γ，調整 φ，把 B0 放大成 B1～B7
    只需在小模型上搜尋一次，避開大模型上搜尋的高成本
  • 成果：B7 在 ImageNet top-1 84.3%，比當時最佳模型小 8.4 倍、推論快 6.1 倍；compound scaling 也可用在其他架構（MobileNet +1.4%、ResNet +0.7%）
  • EfficientNet-B0 由神經架構搜尋（Neural Architecture Search, NAS）自動搜尋，同時考慮準確率與 FLOPS；主要區塊為 MBConv（≈ depthwise ＋ pointwise ＋ skip connection，源自 MobileNetV2）
  • 優點：準確率與運算效率比高、B0～B7 適應多種場景、遷移學習表現佳
  • 缺點：Baseline 依賴 NAS、搜尋成本高；B6、B7 記憶體需求大、訓練慢；FLOPS 低不等於實際速度快

公式：EfficientNet Compound Scaling（不考）

$$\text{depth}=\alpha^{\phi},\quad \text{width}=\beta^{\phi},\quad \text{resolution}=\gamma^{\phi},\qquad \alpha\cdot\beta^2\cdot\gamma^2\approx2,\ \ \alpha,\beta,\gamma\ge1$$
  • φ 每增加 1，總運算量約加倍；寬度與解析度平方是因為 FLOPS 與它們成平方關係（見 2.7）
  • 驗證 B0 係數：\(1.2\times1.1^2\times1.15^2=1.2\times1.21\times1.3225\approx1.92\approx2\)

🎯 目的：用一個係數 \(\phi\) 同時按比例放大深度、寬度、解析度，而且 \(\phi\) 每加 1 運算量約加倍。

🔁 後續用途 補充

  • 有更多運算資源時，知道該怎麼平衡地放大模型（B0 → B7），而不是只加深或只加寬。

逐步展開：φ = 1 和 φ = 2 時各放大幾倍

  1. φ = 1：深度 \(\alpha^1=1.2\)、寬度 \(\beta^1=1.1\)、解析度 \(\gamma^1=1.15\)（224 → \(224\times1.15\approx258\)）。
  2. 運算量：由 2.7，運算量 \(\propto\) 深度 × 寬度² × 解析度²：\(1.2\times1.1^2\times1.15^2\) 寬度平方是因為 \(C_{in}\)、\(C_{out}\) 都變；解析度平方是因為 \(H\)、\(W\) 都變。
  3. 一項一項乘：\(1.1^2=1.21\)、\(1.15^2=1.3225\)；\(1.2\times1.21=1.452\)；\(1.452\times1.3225\approx1.92\approx2\)
  4. φ = 2：每個係數平方：深度 \(1.2^2=1.44\)、寬度 \(1.1^2=1.21\)、解析度 \(1.15^2\approx1.32\)。
  5. φ = 2 的運算量：\((1.92)^2\approx3.7\approx2^2\)。φ 每加 1，運算量約乘 2。

Compound Scaling：深、寬、解析度一起長（不考）

預設是講義的 φ = 1（α = 1.2、β = 1.1、γ = 1.15）。拉 φ 看三個維度各放大幾倍、運算量漲多少；也可以改成「只放大一個維度」，比較在同樣的運算量下三者的差別。

6. 常見觀念陷阱

  • ResNet 解決的是「優化困難」，不是過擬合：深層網路變差時訓練誤差也變差，所以不是 overfitting。
  • \(H(x)\) 是目標映射、\(F(x)\) 是殘差，堆疊的層學的是 \(F(x)\)。
  • Inception 各分支必須 same padding、stride 1，寬高才一致、才能串接；串接是「通道疊在一起」而不是數值相加。
  • ResNet 的捷徑是「相加」，所以 \(F(x)\) 和 \(x\) 的形狀必須相同；Inception 的串接是「通道數相加」補充。
  • Max pooling 不改變通道數，所以 Inception 在 pooling 後要接 1×1 壓通道。
  • 輔助分類器只在訓練時用，推論時移除。
  • 參數少 ≠ 運算少 ≠ 實際速度快：SqueezeNet 參數少但運算量甚至高於 AlexNet；MobileNet／EfficientNet FLOPS 低，但 depthwise conv 在 GPU 上未必快。
  • α 影響參數與運算（約 α²）；ρ 只影響運算（約 ρ²），參數不變。
  • （不考）EfficientNet 係數的符號：這裡的 α、β、γ 是深度、寬度、解析度的縮放係數，和 MobileNet 的 α（寬度）不同，也和 C3 BN 的 γ、β 不同。
  • 為什麼寬度、解析度要平方：FLOPS 與 H×W 及 Cin×Cout 成正比，兩個維度同時放大；深度只是層數式的線性增加。
  • GAP 不適合直接用在偵測、分割，因為丟了位置資訊；小物體可改用 Global Max Pooling。
  • VGG16 的 16 = 13 Conv ＋ 3 FC（有參數的層），Pooling 不算。
  • 講義筆誤：AlexNet 頁的「ILSVRX」應為 ILSVRC；LeNet 頁「再接另一格」應為「另一個」。

用途：① 作為瓶頸層壓低通道數、減少後續 3×3／5×5 的運算量；② 接在 max pooling 後調整通道數（pooling 不改通道數）。same padding 與 stride 1 讓各分支輸出寬高一致，才能在通道方向串接（在 2.4 的元件取消 same padding 就會看到無法串接）。

4.（計算）輸入 16×16×32，輸出 16×16×64（3×3 kernel、same padding）。請分別計算一般卷積與 depthwise separable convolution 的乘法次數，以及兩者比值。

看解答
一般卷積：\(16\times16\times64\times(3\times3\times32)=4{,}718{,}592\)。Depthwise：\(16\times16\times32\times9=73{,}728\)；Pointwise：\(16\times16\times32\times64=524{,}288\)；合計 598,016。比值約 0.1267（約 1/7.9），與公式 \(1/64+1/9\approx0.1267\) 一致（可以在 2.9 的元件按「自我測驗第 4 題」驗算）。

5.（計算）一個 Fire module 的輸入為 128 通道，\(s_{1\times1}=16\)、\(e_{1\times1}=64\)、\(e_{3\times3}=64\)。請計算它的參數量（含 bias），並與直接用 3×3 卷積把 128 通道轉成 128 通道比較。

看解答
squeeze：\((1\times1\times128+1)\times16=2{,}064\)；expand 1×1：\((16+1)\times64=1{,}088\)；expand 3×3：\((3\times3\times16+1)\times64=9{,}280\)；合計 12,432，輸出 64 + 64 = 128 通道。直接 3×3 卷積：\((3\times3\times128+1)\times128=147{,}584\)，約是 Fire module 的 11.9 倍。關鍵在 squeeze 先把 3×3 的輸入通道從 128 壓到 16（策略二），且一半輸出改用 1×1（策略一）。

6.（選擇）把 7×7×512 的特徵圖接到 1,000 類輸出。用 GAP 取代「Flatten ＋ FC」時，下列何者正確？

(C)。Flatten 後 25,088 維接 1,000 類：\((25{,}088+1)\times1{,}000=25{,}089{,}000\)；GAP 後 512 維：\((512+1)\times1{,}000=513{,}000\)。(A) GAP 沒有參數；(B) GAP 輸出長度只看通道數；(D) GAP 丟掉了位置資訊。

7.（選擇）下列模型與其核心特點的配對，何者錯誤？

(A)。多種 kernel 並行再串接是 Inception；VGG 是全部用 3×3 卷積規整地堆疊（見 4.1 總表）。

8.（選擇）ResNet 與 DenseNet 把前面的特徵傳到後面的方式，下列何者正確？

(C)。ResNet 的捷徑是相加，形狀必須相同；DenseNet 把前面所有層的輸出在通道方向串接，通道數越來越多（見 C4-2）。

9.（選擇）要把模型放到手機上，最主要考慮參數少、運算量低，下列哪個模型最適合？

(D)。MobileNet 用 Depthwise Separable Conv 大幅降低運算量（約 4.2M 參數），還能用 α、ρ 再縮小；VGG16 有 138M 參數，ResNet-152、Inception 也都偏大。
